# 报文夹具

每个 `.hex` 文件是一份 S7comm 报文的逐字节快照，测试用它做**字节级**断言。

## 文件格式

```
# name:      简短标识
# source:    spec | capture
# direction: request | response
# note:      这份报文想固定住什么行为
03 00 00 1f  02 f0 80
32 01 00 00  00 02 00 0e  00 00
```

`#` 开头是注释；正文只认十六进制字符，空格和换行随意排版。

## `source` 的两种取值，含义完全不同

| 值 | 含义 |
|---|---|
| `spec` | 按协议规范推导出来的。能锁住"代码行为不变"，但**不能证明真实 PLC 认这份报文** |
| `capture` | 从真实设备抓的包。这才是协议正确性的唯一权威依据 |

**当前所有夹具都是 `spec`。** 手上没有真实 PLC，因此它们的作用是回归保护——
移植协议代码时改错任何一个偏移量，测试立刻会红。但"西门子是不是真这么应答"这个问题，
只有真机能回答。

## 拿到真机后怎么替换

见 [`docs/protocol-fixtures.md`](../../../docs/protocol-fixtures.md)：抓包一次，
把 `source` 改成 `capture` 并补上设备型号和固件版本，测试代码一行都不用动。
